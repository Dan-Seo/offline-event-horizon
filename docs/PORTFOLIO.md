# VASTNESS — 포트폴리오로 설명하기

이 프로젝트는 지친 사람이 잠시 머무를 수 있는 브라우저 공간을 만드는 창작·공학 작업이다. 사용자가 문제와 방향을 제안했고, 코드 작성·절차적 에셋 생성·브라우저 검증에는 AI 에이전트를 폭넓게 사용했다. 지원서에는 본인이 실제로 수행한 설계, 촬영, 분석, 수정만 자신의 기여로 적는다.

## 지금 제시할 수 있는 증거

- 배포된 상호작용 공간과 공개 소스. 기존 우주 렌더러를 보존하면서 수면·숲·안개·생명체를 같은 좌표계에 연결했다.
- 클릭 시점 제어, 자동 이동 중 수동 개입, 터치, 대체 렌더링의 재현 가능한 브라우저 검사.
- 품질 단계에 따른 프레임 간격, 리소스 예산과 시각적 절충. 결과는 `QA-2.0.md`에 실제 측정 환경과 함께 기록한다.
- GPU 힘 적분과 시각적 근사의 경계. 물의 반사와 생명체의 움직임을 완전한 유체·생태 시뮬레이션으로 설명하지 않는다.
- 한국어·영어 안내와 실제 조작을 확인하는 튜토리얼, 자동 이동 실패의 재현·수정 기록. 2.1의 중력 실험은 에너지 오차·고정 시간 간격·흡수와 탈출을 검증했으며, 소수의 CPU 시험 입자와 대규모 GPU 배경 입자를 구분한다. 검증 기록은 `QA-2.1.md`에 있다.
- 2.2의 선택형 블랙홀 관측은 슈바르츠실트 광선 방정식, 낙하자의 고유시간, 주파수 전달을 구현한다. 광자구 궤도·보존량·적분 간격에 따른 수렴을 확인하고, 문헌의 모형과 화면을 위한 근사를 `RELATIVITY.md`에 구분했다. 이를 수치 모형을 구현하고 검증한 공학 사례로 설명할 수 있다. 새로운 일반상대론 연구나 CV/SLAM 알고리즘 기여로 설명하지 않는다.

3.0의 `/lab`은 같은 PILGRIM과 지형으로 RGB-D, 법선, 의미 라벨, 합성 IMU, 정답 자세를 생성한다. 별도 워커는 RGB 영상과 깊이만 받아 특징점 추적·이상치 제거·강체 변환으로 이동을 추정한다. 그 관측으로 만든 작은 지도가 실제 자동 주행의 경로 선택에 쓰인다. 정답 위치를 추정치로 복사하지 않으며, 물리적 접촉에 쓰는 정답 지형은 계획기와 분리했다. [구현과 한계](PILGRIM.md), [검증 기록](QA-3.0.md)을 함께 제시한다.

적절한 소개는 **“WebGPU 합성 환경에 센서가 달린 탐사체, 관측 기반 지역 주행, 기초 RGB-D 시각 주행거리 추정과 정답 궤적 평가를 구현한 시스템”**이다. 새로운 SLAM 알고리즘, 실제 로봇에서 검증된 자율주행, 심리적 회복 효과로 소개하지 않는다. 작은 원시 센서 기록을 내려받아 브라우저 밖에서 같은 추정기로 재실행할 수 있어, 예쁜 궤적 그림 이상의 검증 자료를 남긴다.

이 구현은 CV·로봇 인지에 연결되는 공학 포트폴리오가 될 수 있지만, 독창적인 연구 기여와는 구분한다. 지표를 이해하고 실패 조건을 직접 바꿔 분석한 후 본인의 기여 범위를 설명하는 것이 중요하다.

## CEE · computer vision으로 이어갈 구체적인 다음 작업

작은 실제 장소 하나를 직접 촬영해 가상 안식처의 바위·정원 일부로 옮긴다. 예를 들어 캠퍼스의 허가된 조경 바위처럼 움직임이 적고 표면 특징이 있는 대상을 고른다. 촬영 계획, 복원 실패 원인, 형상 손실과 실시간 렌더링 비용의 관계가 본인이 설명할 수 있는 핵심 자료가 된다.

질문 예시: **같은 사진 기반 공간을 어느 정도 단순화해야 형태 인식을 유지하면서 저사양 브라우저에서 편하게 탐색할 수 있을까?**

`RECONSTRUCTION.md`의 수집·복원·검증 절차를 따라 원본, 중간 모델, 최적화 모델을 비교한다. 카메라 등록률과 재투영 오차만으로 실제 형상의 정확도를 단정하지 않는다. 독립적인 치수나 기준 스캔이 있으면 별도로 비교한다. COLMAP을 사용한 오프라인 복원은 본인이 새 SLAM 알고리즘을 개발했다는 뜻이 아니다.

## 사례 연구 구성

1. 문제: 쉬려고 들어온 사람이 조작을 익히느라 다시 피곤해지는가?
2. 설계: 수동 조작을 우선하고, 아무것도 하지 않아도 반응하는 환경을 만들었다.
3. 구현: 입력→카메라→GPU 상태→렌더링. 시각적 실패 사례와 수정 전후 화면을 제시한다.
4. 검증: 브라우저 자동화와 사람의 체험 평가를 구분한다. 실제 시행한 평가만 결과로 쓴다.
5. 개인 기여: 직접 결정·촬영·분석·수정한 내용과 AI 및 외부 도구가 수행한 내용을 나란히 밝힌다.
6. 한계와 다음 실험: 실제 기기, 장시간 체류, 사진 복원, 사용자 평가 등 미완료 항목을 명시한다.

현재 사용자 연구 참가자 수는 **0명**, 본인이 촬영한 복원 데이터는 **아직 없음**이다. `FORMATIVE-STUDY.md`는 시행 전 계획서다. 결과를 미리 채우지 않는다.
