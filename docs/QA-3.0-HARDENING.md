# PILGRIM 3.0 hardening: production evidence

Carry could previously accept an old capture using its delivery time, and reset could unlock an unresolved sensor transaction. This release uses capture-time freshness and generation/request/capture ownership through settlement, with reset invalidating cached routes. A separate Astra-low worker implemented the repair, an Astra-low reviewer independently certified the critical contracts, and Terra medium handled documentation and QA evidence. The existing VO, map, world and vehicle models were preserved.

## September 22: Carry clarity and independent Fable review

Baseline `9e02ad6`; first implementation `a75f9f5`. These results are distinct from the September 10 reports above. The baseline passed 89 tests, build, 16 journey checks and 41 lab checks in installed Chrome 153.0.8010.53. The first implementation passed 93 tests, lint, build, 17 journey checks and 41 lab checks. Its 120-second quiet Carry traveled 142.49 units, scheduled one scenic rest and entered no failed-search hold in that interval. Subsequent coastal traversal, manual handover, touch release and recovery passed. A single unit corresponds to one meter in the metric sensor contract.

The actual first-candidate 32-frame turning recording replays all 31 comparable relative transforms: maximum translation difference 3.55e-15, rotation difference zero. Against separately recorded truth it has 31 tracked / 32 total, zero LOST, distance 13.2013 m, unscaled SE(3) ATE 0.09709 m, aligned orientation RMS 0.38116 rad, one-second RPE translation 0.15710 m / rotation 0.009461 rad, 23 pairs (interval tolerance 0.26 s), endpoint drift 0.27585 m. The opposite-turn holdout also passes all 41 lab checks and replays 31 pairs; ATE 0.10495 m, aligned orientation RMS 0.44767 rad, RPE translation 0.19107 m / rotation 0.010131 rad, zero LOST. Both are 32-frame, 192x128 RGB-D recordings with no scale fit. The holdout used `QA_TURN=left npm run qa:lab` (PowerShell: `$env:QA_TURN='left'; npm run qa:lab`). Neither algorithm nor threshold was tuned after seeing it.

Replay agreement is reproducibility; separately recorded truth comparisons are accuracy evidence. These short curved paths pass the existing conditioning test but their orientation alignment remains weak; they do not establish global localization accuracy. The initial STARTING sample is counted in the denominator and is not called LOST. The accuracy gates remain lost fraction <=0.1, RPE translation <=0.5 m, endpoint drift / distance <=0.2. Stationary/near-collinear ATE remains null. The unchanged tests independently recover known metric transforms, reject outliers, enforce units, and handle missing tracking and restarted segments. The new actual-worker replay test produces identical VO, routes and director commands with truth absent or corrupted, including deliberately corrupted labels and normals.

Fable B reviewed `a75f9f5` and the actual before/after images and returned REVISE. Both findings reproduced in failing tests: a beauty event overwrote a blocked hold with `watching` until the old cooldown expired; a stale render interval erased confirmation between two individually fresh safe captures. Astra separated the event-watch timer from the failed-search timer and removed only that frame-driven reset; stale or unsafe incoming observations and lifecycle resets still clear confirmation. The new tests also check that a new ride cannot inherit an old watch. All 95 tests and lint pass after repair. Fable requested that browser QA read the actual rest whisper rather than restating the getter's definition. The journey check now samples the DOM, allowing for React's periodic snapshot update. Fable judged the quieter material legible in the actual starting-sea screenshots; this was screenshot review, not Fable browser interaction or a human comfort study.
